## 实现和边界（当前 candidate4；历史数据另行标注）

candidate4 的七项配对控制（含新增 `generic-call-fallback`）、数组强制层诊断
和完整 24 场景矩阵均已完成并发布；本节描述实现，不把旧候选收益转移给新版本。
候选 benchmark 二进制 SHA-256 为
`b758218bdd1d746083f34693a78d42607bc663086fa3e64e2d2f98384d17c2a3`，
相同新版 harness 的旧运行时基线为
`874748d78956fcf71e96224cdc8a2ae8dea3a5dcc0c78a84721d0b3eb5bfb294`。

- **Bool tagged-frame 与有限直调。** 稳定 Bool 参数仍可进入普通 Tier 2；
  candidate4 另为无副作用的 Int32/Bool 分支叶函数提供有限 compiled-to-compiled
  ABI，保留类型和数值失败路径。原 `generic-call-entry` 脚本未变，但现在
  可走直调，不能用其收益宣布 generic CALL 成本已经消失。新增
  `generic-call-fallback` 使用 `(Int32, Bool, Object)` 参数及可观察的属性写入，
  明确保留通用调用边界；每次重置计数并消费结果，独立对照同脚本基线和 Bun。
- **数组自动试编译。** 对已有循环/元素访问和稳定 Object 参数的候选，
  允许混合数值反馈进入现有 profitability trial。保留预算、收益判断、
  类型、bounds、buffer 和数值保护。现有直线区域已复用部分 count/data
  元信息；不将此写成新实现的循环外提或全面 bounds-check elimination。
- **原生属性 guard。** 用活 receiver 的 shape 指针及非零 generation token
  作 O(1) 检查，替代 rooted hit 的 C shape helper 和描述符逐项扫描。
  token 按运行时单调分配，布局/描述符改变前失效，克隆及新分配重新观察；
  耗尽后停止产生新观察，不复用旧 token。只接受已观察的 own-data 属性，
  写入需 writable，旧值和新值需匹配 primitive tag。guard 与访问之间没有
  helper 或 safepoint；不能由反馈指针读取已释放的 shape。
- **所有权与恢复。** 只有全部 live stack 已证明为参数/局部根或 primitive
  时才用原生 hit。未知来源或临时 owner 保留 helper 路径。miss 在原始 opcode
  重建参数、局部、精确 pre-op 栈和 PC，经原所有权桥恢复解释器；先前已完成
  的属性副作用不重放。保留 loop poll、generation 和 GC 生命周期约束。
- **ABI 与缓存取舍。** 新 `PropertyLayout` 导出对象 shape、属性表及 shape
  token offset；ABI minor 升至 21，加入 size、layout fingerprint、offset 范围
  和 build fingerprint 检查。candidate2/3 的额外 PC bitset/紧凑缓存已移除，
  历史 192/168 字节函数布局不代表当前版本；shape token 本身仍有内存成本。
- **返回记账。** 常驻 artifact 安全引用缓存减少重复索引，删除/替换/淘汰时
  清空；不跳过 benefit 或 last_used。冷 metrics 按变更发布，native 入口/出口
  与异步编译计数保持精确。

`FeedbackRepresentation` 的 Bool 变体及新增直调 ABI 是需复核的公开兼容面；
已有 fingerprint tag 保持，新的 ABI 版本和归档源码用于区分测量版本。

## 测量协议

所有引擎先执行一次，再执行完全相同的 64 个十调用预热批次，最后计时
一个十调用批次。共享 JS driver 消费全部结果，checksum 在计时外完成；
异步结果逐个完成。每配置丢弃五个进程，保留三十个交错独立进程。
Bun 使用默认 flags。QuickJS 列取候选版同一二进制的无 JIT backend 模式，
quickjs-jit 列使用生产 automatic 配置。

绝对值为 ms/十调用批次的中位数。速度为逐对延迟比的几何平均，95% 区间
通过 10,000 次配对 bootstrap（seed 20260909）计算；不是表内中位数之比。
同一配对的 Bun 同时用作旧版和候选的外部参照，其相对 Bun 速度的改善比
恰好等于旧 JIT 延迟 / 候选延迟，不能用两个独立区间的端点相除。

这是固定等量预热后的批次延迟，**不是引擎峰值或已配平稳定层级的吞吐**。
保留每个预热批次曲线和计时段前后的 metrics；后续 readiness 计时单列诊断。
QuickJS 仍包含一次 Rust 外层调用/Promise bridge，Bun 包含对应 JS 调用。
计数包含 driver 和 workload，不用累计安装数推断单个函数的执行层级。
本轮未测 JS 吞吐窗口、Bun 冷启动或同条件 settled-state，对这些目标不作
完成声明。历史 v1 表与本轮预热和计时边界不同，不能直接相除计算优化收益。

环境：Linux x86_64 / Intel Core i7-13700KF，CPU 2 affinity，powersave，
共享桌面，未独占核心。正式候选采样期间不运行编译或 sanitizer。
